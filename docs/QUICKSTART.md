# QUICKSTART

시험이나 리허설에서 이 키트를 쓰는 순서. 키트가 안 될 때도 진행이 멈추지 않도록 비상 경로를 같이 적었다.

## 0. 시작 직후 (전체의 0–7%)

1. 과제 화면의 터미널을 연다. 아직 **codex를 실행하지 않는다.**
2. 키트를 받는다. 과제 폴더 **밖**(홈 폴더)에 둔다. 제출 저장소에 키트 파일이 섞이지 않게 하기 위해서다.
   ```bash
   git clone --branch exam-v1 https://github.com/<아이디>/hackathon-kit.git ~/hackathon-kit
   ```
   Windows PowerShell이면 `~` 대신 `$HOME`을 쓴다.
3. 설치한다. `<과제 폴더>`는 README·data가 있는 폴더다.
   ```bash
   python ~/hackathon-kit/install.py --workspace <과제 폴더>
   ```
   `python`이 없다고 나오면 `py` 또는 `python3`으로 바꾼다.
4. 과제 폴더에서 codex를 실행하고 `/skills`를 친다. `kit-start` 등 9개가 보이면 성공이다.
   - 안 보이면: `install.py ... --also-codex-home` 후 codex를 다시 켠다.
   - 그래도 안 보이면: **고치지 않는다.** `~/hackathon-kit/PROMPTS.md`의 긴 프롬프트를 복사해 쓴다.
5. 그동안 README·상세 안내를 **직접** 읽고 흔적을 표시한다(범주 컬럼 값, 변경·예외 문구, 시간 기준).

## 1. 파악 (7–20%)

- 나: `PROMPTS.md`의 담당자 질문 ★ 3개부터 한 메시지에 하나씩 보낸다. 답은 AGENTS.md "담당자 확인 사항"에 `[확정 N분]` / `[미정 N분]`으로 적는다.
- AI: `$kit-start` → 보고 확인 → `$kit-trapmap`
- 나: 2차 질문 초안을 숫자가 맞는지 확인하고 3~5개만 보낸다.

## 2. 뼈대 (20–30%) — 체크포인트 1

- `$kit-plan`. PLAN에 동결·제출 시각이 실제 시계 시각으로 적혔는지 본다.
- AI의 "왜" 질문에 3문장으로 답한다: 코드 지점 → 전후 숫자 → 정책이 틀리면 파급.

## 3. 규칙 (30–65%) — 체크포인트 2

- `$kit-rule 항목 3,5,7` 처럼 함정 지도 번호를 2~4개씩 준다.
- 묶음마다 "실제 1건 따라가기"를 내가 다시 계산한다.
- 컨텍스트가 길어지면: HANDOFF 갱신 → `/new` → HANDOFF.md 하단 문구로 이어 간다.

## 4. 검증 (65–78%) — 체크포인트 3

- `$kit-verify`. ★ 그룹을 설명 못 하면 건수·사례를 붙여 담당자에게 실제로 보낸다.

## 5. 정리·동결 (78–83%)

- `$kit-docsync`. check_submit 실패 0, 커밋 확인. **이후 새 기능 없음.**

## 6. 서술형 대비 (83–92%)

- `$kit-essay`. E4 퀴즈에서 **답은 내가 쓴다.** 6문제 뒤 외울 숫자 10개·파일:줄 5개를 받는다.

## 7. 점검·제출 (92–100%)

- `$kit-final` → "제출 가능"이면 **94% 시점에 제출을 시작한다.**
- 서술형 6문항은 AI·붙여넣기 없이 답한다: 결론 → 근거 → 숫자 → 파급 → 다음 행동.

## 비상 경로 요약

| 문제 | 할 일 |
| --- | --- |
| clone 실패 | 키트 없이 진행. PROMPTS.md 내용은 외운 것으로 |
| 스킬이 안 보임 | PROMPTS.md 긴 프롬프트 복사 |
| 스크립트 오류 | AI에게 같은 일을 짧은 코드로 직접 하게 하고 넘어감 |
