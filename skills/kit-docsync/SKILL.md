# kit-docsync: 요구 재확인 + 문서 정합

## 1. 요구 재확인 (가장 먼저)
REQUESTS.md의 모든 줄을 실제 출력(API 응답·화면 HTML·출력 파일)에서 수용 기준대로 확인한다. 안 보이면 '완료'를 지우고 보고한다. 고칠 시간이 없으면 `보류(이유)`로 바꾸고 REPORT 한계에 적는다.

## 2. 문서 (templates 양식, 맨 위 "현재 상태" 한 칸을 덮어쓴다)
- REPORT 첫 줄: 무엇이 되고 무엇이 안 되는지. 핵심 숫자, 확정/잠정, 검증 범위, 다음 검증.
- DECISIONS: 결정마다 현재 상태 하나(확정 또는 잠정). 같은 결정이 '미확인'과 '확정'으로 함께 적히지 않게. 변환표는 실제 코드 순서대로, 큰 변화는 원인별 분해.
- PLAN: 단계 상태를 실제와 맞춘다. HANDOFF: 실행 명령·현재 상태·남은 일·미확정 정책과 승인 대상 5줄.

## 3. 마무리
`check_submit.py --pytest` 실패 0까지 → 커밋. 이후 기능 변경 없음.

## 보고 (10줄)
REQUESTS 완료/보류 수, 고친 불일치 수, check_submit 결과, 커밋 해시.
