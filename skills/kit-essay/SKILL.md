# kit-essay: 서술형 대비 (E1–E4)

서술형은 내 작업 기록(프롬프트·코드·문서 숫자)에서 나오고, 약점과 빈틈을 겨냥한다. 예상 질문 6개를 맞히려 하지 말고 영역 전체를 덮는다.
**답은 내가 쓴다. 너는 근거 위치를 주고 채점만 한다.**

## E1 지시 타임라인
이 세션에서 내가 보낸 지시를 시간순 표로: 경과 분(모르면 커밋 시각) · 지시 요지 · 바뀐 파일·커밋 · 이유. 방향을 바꾼 지점과 **내가 지시하지 않았는데 네가 정한 것**을 따로 표시한다.

## E2 결정·숫자 카드 (templates/ESSAY_CARDS.md)
DECISIONS·REPORT·테스트·코드에서 결정과 숫자를 전부 뽑는다. 카드마다: 결정/숫자 · 파일:줄 · 채택 결과 · 대안 결과와 증감 방향 · 정책이 틀리면 누가 무엇을 잘못 보나 · 확인 방법.
- 큰 숫자 변화는 원인별 기여로 분해한 식을 적는다.
- 테스트 기대값마다 손계산 식을 적는다 (예: (40+90)/(50+150)×100 = 65%).

## E3 사각지대
내가 직접 다루지 않은 곳 8개를 위험 순으로: 테스트에 없는 입력, 문서와 코드가 다른 곳, 네가 임의로 정한 것, 실패·오류 시 동작, 처리 순서를 바꾸면 달라지는 곳, 담당자 답과 다르게 구현된 곳. **근거 위치만 주고 답은 주지 않는다.**

## E4 반례 퀴즈
- E2·E3에서 한 문제씩 낸다. 내가 이미 연습한 주제는 빼고 다음으로 나올 만한 것을 고른다.
- 질문 형태를 섞는다: "왜 이 순서인가", "이 정책이 틀리면", "이 숫자를 손으로 다시 계산하면", "어떤 테스트가 이것을 지키나".
- 내가 결론 → 근거(파일:줄) → 숫자 → 파급 → 다음 행동으로 답하면, 코드·숫자와 대조해 **틀린 것과 빠진 요소만** 짚는다.
- 이어서 순서나 값을 바꾼 작은 반례로 한 번 더 묻는다.
- 6문제 뒤, 내가 외울 숫자 10개와 파일:줄 5개를 골라 준다.
