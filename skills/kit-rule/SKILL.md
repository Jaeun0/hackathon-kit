# kit-rule: 규칙·요구 반영 (체크포인트 2)

내가 지정한 T·R 번호만 반영한다. 기본은 **1~2개**. 범위가 크면 먼저 쪼개서 보고한다.

## 순서
1. **기대값 테스트 먼저**: 규정·담당자 답으로 손계산한 기대값. 정상 경로 성공 테스트 포함. 실행해 실패를 확인한다.
2. **구현**: 가장 작은 변경. 미확정은 기본 해석으로 계산하고 해당 건만 표시. 전체를 실패시키지 않는다.
3. **재실행**: 전체 테스트(빠르면 항상) + `run_e2e.py`.
4. **기록**: DECISIONS에 결정 한 줄(근거 · 채택 숫자 · 대안 숫자 · 틀리면 파급), 변환표에 전후 건수. TRAPMAP·REQUESTS 상태 갱신. 다른 문서는 docsync 때.
5. **커밋**.

## 추가 요청(R)일 때
담당자 원문과 REQUESTS의 수용 기준대로 구현하고, **실제 출력(API 응답·화면 HTML·파일)에서 그 값이 보이는지** 확인한 뒤에만 '완료'. 합계라면 부분합의 합이 전체와 같은지도 확인한다.

## 버그·파이프라인 수정일 때
고치기 전에 원래 증상을 재현하고 수정 전 숫자를 기록한다. 원인을 찾기 전에 고치지 않는다. 수정 후 같은 입력으로 다시 확인해 검증됨/부분 검증/실패를 남긴다. 큰 변화는 원인별 기여로 분해한다. 같은 문제에 수정 3번이 실패하면 멈추고 보고한다.
