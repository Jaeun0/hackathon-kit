# kit-rule: 규칙 묶음 구현 (체크포인트 2)

내가 지정한 함정 지도 항목 번호만 반영한다.

## 순서 (묶음마다)
1. **기대값 테스트 먼저**: 규정·담당자 답으로 손계산한 기대값을 테스트에 쓴다. 정상 경로가 성공하는 테스트도 넣는다. 실행해 **실패하는 것을 확인**한다.
2. **구현**: 가장 작은 변경으로 통과시킨다. 미확정 항목은 기본 해석으로 계산하고 해당 건만 표시한다. 전체를 실패시키지 않는다.
3. **재실행**: 전체 테스트 + `run_e2e.py`. 숫자로 확인한다.
4. **DECISIONS.md**: 결정마다 근거(조항·담당자 답 시각) · 채택 결과 숫자 · 대안 결과 숫자와 방향 · 정책이 틀리면 누가 무엇을 잘못 보게 되는지. 변환표에 이번 단계의 전후 건수를 실제 코드 순서대로 추가한다.
5. **커밋**: 메시지에 무엇을 왜 바꿨는지.

## 버그·파이프라인 수정 유형이면
- 고치기 전에 **원래 증상을 재현**하고 수정 전 숫자를 기록한다. 원인을 찾기 전에 고치지 않는다.
- 수정 후 같은 입력으로 원래 증상이 사라졌는지 다시 확인하고 판정을 남긴다: 검증됨 / 부분 검증 / 실패.
- 큰 숫자 변화는 원인별 기여로 **정확히 분해**한다 (예: 1,200 → 900 = 조인 증식 250 + 중단 제외 50). 합이 안 맞으면 보고한다.
- 같은 문제에 수정 3번이 실패하면 멈추고 접근을 다시 설명한다.

## 보고 후 멈춤 (15줄)
한 일 / 파일:줄 / 실제 1건 따라가기(입력 → 중간 → 최종) / 테스트·e2e 숫자 / 미확인 / 나에게 "왜" 질문 1개.
내 답이 오면 코드·숫자와 대조해 틀린 곳만 짚는다.
