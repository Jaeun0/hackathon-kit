# kit-trapmap: 함정 지도 + 2차 질문 초안

## 1. 함정 지도 (표 하나)
관점 7개를 모두 본다: 대상 범위(범주 값별 포함/제외) / 기준 시점·시간대 / 경계값(이상·초과·정각) / 중복·병합·재시험 / 결측·판단 불가 / 문서 간 불일치 / 변경·예외 문구.

항목마다 칸: 관점 · 근거 위치(파일:줄) · 현재 영향 건수 · 해석 A·B별 결과 차이 · 근거 수준(문서 확정 / 담당자 필요) · 답이 없을 때 쓸 기본 해석.
- **영향 0건도 빼지 않는다.** 다른 날짜 데이터에는 나올 수 있다.
- AGENTS.md "담당자 확인 사항"의 [미정] 항목을 반드시 포함한다.
- 유형별 한 줄 추가: 집계 "분모·기간 경계·중복 기준을 바꾸면 결과 변화량" · 웹 "기능별 지금 동작 여부, 일부 데이터가 이상해도 화면이 뜨는지" · 수정 "테스트가 통과해도 명세상 틀릴 곳" · 원인 "원인 후보와 같이 움직이는 변수와 시간 순서".

## 2. 명세가 말하지 않는 입력 5개
명세에 없지만 다른 날짜 데이터에서 만날 법한 입력 5개를 적는다(예: 제외 대상 값, 정각 경계, 같은 시각 두 기록, 최신 기록이 판단 불가, 빈 날짜). 각각 "합리적인 기대 동작"을 한 줄로. 이후 kit-rule에서 테스트로 고정한다.

## 3. 2차 질문 초안
대상: [미정] 항목 + 함정 지도의 "담당자 필요" + 데이터와 어긋나는 [확정].
- 최대 5개, 영향 큰 순. **한 질문에 한 가지 결정.**
- 각 질문에 컬럼·값, 영향 건수, 실제 사례 ID 1개, 내 기본 해석을 넣어 "네/아니요"로 답할 수 있게 쓴다.
- 담당자에게 자료를 찾아 달라고 하지 않는다. 구체 사례를 못 붙이는 항목은 질문으로 만들지 말고 기본 해석만 적는다.
- 숫자는 실행 결과에서만 가져오고 출처를 괄호로 붙인다.

## 보고
함정 지도 표 → 입력 5개 → 질문 초안. 그다음 멈춘다. 질문 전송과 답 기록은 내가 한다.

참고: 질문 규칙은 github/spec-kit `clarify`(MIT), 입력 5개는 obra/superpowers `writing-plans`의 Review Focus(MIT)를 바탕으로 했다.
