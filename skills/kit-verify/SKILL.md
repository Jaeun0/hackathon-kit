# kit-verify: 검증 (체크포인트 3)

원본 data/는 건드리지 않는다. 검증용 파일은 `verify/` 폴더에 둔다. 홀드아웃 데이터 사본은 `verify/holdout/`에 만든다(install.py가 git 제외 설정을 해 둔다). 설정 JSON·기대값·대조 스크립트는 `verify/`에 두고 커밋한다.

## 1. 독립 재계산
- 본 코드를 import하지 않는 별도 스크립트로 규정대로 다시 계산한다(다른 방식: SQL, csv 모듈, 손계산 표).
- 날짜·그룹별로 대조해 차이 건수와 원인을 보고한다.
- 한계를 적는다: 두 구현이 같은 잘못된 정책을 공유하면 차이 0건이어도 정책이 맞다는 증거가 아니다.

## 2. 자가 홀드아웃
- kit-tools `make_holdout.py`로 날짜를 옮기고, 함정 지도와 "명세가 말하지 않는 입력 5개"의 변형을 넣는다(설정 JSON을 `verify/holdout.json`으로 남긴다).
- 기대값은 HOLDOUT_LOG와 규정으로 손계산한다. 본 코드 출력을 복사하지 않는다.
- 지정 명령으로 `run_e2e.py` 실행: 실패 0건이어야 하고, 손계산 기대값과 일치해야 한다.

## 3. 재스캔
- `slice_report.py`로 결과를 범주 컬럼별·기간별로 나눈다. ★ 그룹마다 설명을 한 줄씩 붙인다. 설명이 안 되면 담당자 질문 문장(건수·사례 ID·기본 해석 포함)을 만든다.

## 보고 후 멈춤
- 세 검증의 숫자와 판정(검증됨 / 부분 검증 / 실패)
- 실측 자료(공식 리포트 등)가 없으면 "실측 대조 미확인"과 대신 한 방향 검증을 명시
- 나에게 "왜" 질문 1개: 기대값 하나를 내가 손으로 다시 계산하게 하는 질문

참고: obra/superpowers `verification-before-completion`(MIT) — 증거 없이 완료라고 말하지 않는다.
