# kit-verify: 검증 (체크포인트 3)

원본 data/는 건드리지 않는다. 과제 폴더 `verify/`에는 **스크립트·설정·기대값·SUMMARY.md만** 둔다. 홀드아웃 데이터 사본과 실행 로그는 `~/kit-out/`에 둔다(저장소 루트 pytest가 수집하지 않게).

## 1. 독립 재계산 (필수)
본 코드를 import하지 않는 별도 방식(csv·SQL·손계산 표)으로 다시 계산해 날짜·그룹별 차이 건수와 원인을 본다. 한계: 두 구현이 같은 잘못된 정책을 공유하면 차이 0도 정책이 맞다는 증거가 아니다.

## 2. 자가 홀드아웃 (필수)
`make_holdout.py`로 `~/kit-out/holdout/`에 날짜를 옮기고 함정·"입력 5개" 변형을 넣는다(설정은 `verify/holdout.json`). 기대값은 손계산해 `verify/`에 리터럴로. 지정 명령으로 `run_e2e.py` → 실패 0·기대값 일치.

## 3. 재스캔 (시간 관문에 여유가 있을 때만)
`slice_report.py`로 범주·기간별 ★ 그룹에 설명 한 줄. 설명이 안 되면 담당자 질문 문장.

## 마무리
결과를 `verify/SUMMARY.md` 10줄로 쓰고(명령·숫자·판정), 저장소 루트에서 `python -m pytest`가 통과하는지 확인한 뒤 커밋한다. 실측 자료가 없으면 "실측 대조 미확인"을 명시한다.
